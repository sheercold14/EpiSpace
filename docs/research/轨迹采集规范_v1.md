# 轨迹采集规范 v1（执行者：OmniGibson 采集管线）

> 本文档是采集执行规范，也是论文"数据采集"章节的方法学底稿。
> 下游对接：《QA编排格式与泄漏控制_v1》（问题排布）、《轨迹分类与建图训练_v1》（能力映射与建图训练）、
> 《空间组合泛化Episode数据设计_v1》（研究契约）。
> 现有资产：episode3d-og-static-m2-working（46 场景 T1 轨迹，37 candidate）+ flip/swap 干预对 48 对。

## 0. 第一性原理与总原则

**轨迹 = 在 SE(3)×时间上的采样策略。它诱导的信息结构决定了哪些空间能力可以被考察。**
信息结构由四个正交轴刻画，每类轨迹是四轴上的一个刻意设计的点，而非随机采样：

| 轴 | 取值范围 | 决定 |
|---|---|---|
| A 基线类型 | 平移（视差→深度可推）↔ 纯旋转（零视差） | 深度/尺度 vs 朝向/全景 |
| B 视图重叠 | 稠密链 ↔ 稀疏宽基线 ↔ 零重叠 | 跨视图注册难度阶梯 |
| C 覆盖与揭示 | 全覆盖 ↔ 部分覆盖；先看/后看/永不看 | 认知状态 known/unknown 的结构 |
| D 参照结构 | 场景中心 ↔ 物体中心 ↔ 观察者锚定 | 建图 vs 物体3D vs 视角采择 |

**论文叙事**：每类轨迹对应一个可证伪的能力假设（"若模型具备能力X，则在信息结构Y下应答对Z"）。

### 全局硬约束（所有类型继承，违反即拒收）

1. **端点/站位从房间实例分割内采样**（M2 教训：禁止采到室外/traversability 图的外部区域）；
2. 默认人视高度 1.4–1.6m，路径连续、无碰撞、无穿模（T7 显式变高除外）；
3. 每视图落盘 `rgb/depth_m/instance_id/semantic_id` npz + 精确位姿；通道隔离契约不变
   （model_visible 仅 rgb）；
4. **轨迹不得为任何问题定制**：coverage-first，问题在采集完成后由可见性时间线编译生成；
5. 失败/不合格采集保留在 manifest 并标记原因，不得静默丢弃；
6. **split 继承**：同一场景的所有轨迹类型共享该场景的 split（`scene:<model>` 锁组）——
   T3/T4 等新轨迹属于已分配 split 的场景时必须继承，严禁跨 split。

## 1. 视图角色词汇表（trajectory_plan.json 扩展）

已有：`initial / explore / turnaround / revisit / loop_closure`

## 2. 轨迹类型规格

### T1 覆盖漫游（已有，保持）
- **四轴坐标**：A平移 / B稠密 / C全覆盖+revisit / D场景中心。
- **规格**：8–16 视图，按房间顺序，含 turnaround、revisit、闭环回起点。
- **质量门**：loop RGB PSNR ≥30dB；每视图可见核心实体 ≥3；全轨迹观察实体 ≥15。
- **能力假设**：稠密 ego-motion 下的建图、记忆、出现顺序（VSI-Bench 域）。
- **新增约束（服务 T2 派生）**：共视图必须连通（任意两视图经共视实体链可达），
  且存在 ≥1 个天然断点（两组视图间共视实体为零，如厨房组/客厅组）——采集后机检，
  不满足标记 `t2_derivation: partial`。

### T2 稀疏子采样（派生，零渲染成本）
- **四轴坐标**：A平移 / B稀疏~零 / C部分覆盖 / D场景中心。
- **规格**：编译器从 T1 抽 k∈{2,3,4,5} 视图。控制两参数分档：
  共视度 high(≥5 共同实体)/low(1–2)/zero；朝向差 <45°/45–120°/>120°。
  每子集生成顺序打乱变体（地图应与观察顺序无关）。
- **质量门**：连通子集出可答题；zero 档子集必须真的零共视（机检）。
- **能力假设**：宽基线注册与有限视图心理建模（MindCube-Among / MMSI 域）。

### T3 原地旋转站（新采集，P1 优先）
- **四轴坐标**：A纯旋转 / B相邻高重叠 / C站位局部全覆盖 / D观察者锚定。
- **站位选择算法**：房间几何质心附近、离墙 ≥1m、该站位全景可见实体 ≥8；
  每场景 2–3 站（不同房间）。
- **规格**：位置固定，yaw 均匀扫描，步进 ∈ {45°, 60°, 90°}（即 8/6/4 视图），pitch=0。
- **质量门**：全景并集实体 ≥8；**存在 ≥2 个"仅背向朝向可见"实体**（否则"背后有什么"
  无意义）；零视差标志 `depth_questions_forbidden: true` 写入 plan（禁深度出题）。
- **能力假设**：全景整合、旋转顺序、背后推理（MindCube-Rotation 域）。

### T4 物体环绕（新采集，P1 优先，资产最挑剔）
- **四轴坐标**：A平移(环形) / B相邻高重叠+对视低重叠 / C物体全覆盖 / D物体中心。
- **焦点筛选算法**（按序过滤 scene_ir）：
  ① `symmetry_group` 非旋转对称；② `canonical_front` 置信可用（orientation_evidence）；
  ③ 四周净空 ≥1m（环绕路径无碰撞，用 navmesh/碰撞检查）；④ 非贴墙（背面可拍且
  背面视图中背景实体 ≥3，否则降级为遮挡题源）。
  好焦点：沙发、电视、椅子、冰箱；坏焦点：花瓶、圆桌、吊灯。
- **规格**：半径 1–3m 环绕 6–12 视图，方位角均匀 + 记录逐视图相机-物体方位角；
  **必含一对方位角差 ≈180° 的对视图**；每场景 2 个焦点。
- **质量门**：焦点在全部视图可见且像素 ≥128；对视对存在；背面视图背景实体 ≥3。
- **能力假设**：物体3D/朝向、对面视角同一性、背后场景（MindCube-Around / ViewSpatial 域）。

### T5 双视图对（派生为主 + 少量补采）
- **四轴坐标**：B 全档扫描（这是它存在的意义），其余继承来源轨迹。
- **规格**：从 T1/T3/T4 任取两视图组对，共视度三档各占 ~1/3；
  记录相对位姿 bin（平移距离 × 朝向差）。存量不足的档位补采宽基线专用对。
- **能力假设**：相机-相机关系（MMSI 特色）、跨视图实体绑定、零共视弃答（BLINK/MMSI 域）。

### T6 跨房间桥接（T1 的约束加强版，先审计后补采）
- **规格**：≥3 房间、≥2 门洞；**每个房间必须有 ≥2 个专属锚定实体**（仅在该房间
  视图可见——采集后用可见性矩阵机检）。
- **执行顺序**：先审计现有 46 条 T1 是否已满足（multi_room_rich 44 个中预计多数满足），
  满足者打 `bridge_eligible` 标签，不满足者列入补采清单。
- **能力假设**：全局坐标系整合、跨房间非共视关系（我们的主实验轴）、路线规划（navmesh 真值）。

### T7 高度/俯仰变化（P2 试点 ~20 场景）
- **规格**：复用 T3 站位；三档：0.3m（低视角）/ 1.5m（人视）/ 2.5m + pitch 下倾 30–60°
  （准俯视）。同站位仅高度/pitch 变，位置严格相同（视点不变性的干净对照）。
- **能力假设**：视点不变关系、俯视-平视对齐（认知地图接地的直接监督源）。

### T8 遮挡揭示（P2 试点 ~20 场景，路径规划植入）
- **规格**：搜索 (target, occluder) 对——target 在某方向视线上被大件遮挡
  （instance+depth 联合判定：target 中心投影落在 occluder mask 内且深度更远）；
  路径先经遮挡视角（`occlusion_pass`）再绕过揭示（`reveal`）。
- **落盘**：`occlusion_annotation: {target_id, occluder_id, occluded_views, decisive_view}`。
- **能力假设**：物体恒存、unknown→known 认知转换；与 family 变体
  `decisive_view_deleted` 组成三重一致性。

### T9 干预对（已有管线，接入）
- flip 24 + swap 24 已认证，直接进入 QA 编译；新增类型上可扩展干预
  （优先：T4 焦点物体旋转干预 → 朝向题答案翻转）。

### T10 目标视图渲染（T1 附属，轻量）
- **规格**：每场景选 3–5 个锚定实体对 (origin, facing)（非共线、目标位姿可达），
  渲染 held-out 目标视图；标 `target_holdout`，**永不进入 write 前缀**，仅供 P 原子验证。
- **能力假设**：视角采择的渲染器裁决（ViewSpatial 域，把"标注员想象"换成真值渲染）。

## 3. 采集量与优先级（pilot 预算）

| 优先级 | 类型 | 范围 | 新渲染视图估算 |
|---|---|---|---|
| P0（纯软件，先行） | T2/T5 派生 + T6 审计 + 泄漏机检接入 | 现有 46 场景 | 0 |
| P1 | T3 旋转站 | 46 场景 × 2 站 × 6 向 | ~550 |
| P1 | T4 物体环绕 | 37 候选场景 × 2 焦点 × 8 视图 | ~600 |
| P1 | T10 目标渲染 | 37 × 4 | ~150 |
| P2 | T7 高度 + T8 遮挡揭示 | 各 ~20 场景试点 | ~500 |

命名规范：`<scene>_<class>_seed<k>`（如 `Beechwood_0_int_t3_seed17`）；
同场景同类多轨迹递增 seed；所有新采集进入新 sweep 目录并登记 dataset/releases
working manifest（保留失败记录的规则不变）。

## 4. 产出契约（与 QA 编译器 v2 对接）

- `trajectory_plan.json`：+`trajectory_class`；role 用 §1 词汇表；类型附件：
  T3→`{station_id, yaw_sequence_deg}`；T4→`{focus_entity_id, azimuth_deg_per_view, radius_m}`；
  T6→`{room_anchor_map: {room_id: [entity_ids]}}`；T8→`occlusion_annotation`；
  T10→`{anchor_pair, held_out: true}`。
- `spatial_episode.json / scene_ir.json / quality_report.json` 格式不变；
  类型专属质量门写入 `quality_report.gates.<class>`。
- 通道隔离、family_id、split_group 规则与现契约完全一致。

## 5. 验收标准

**机检（进 verify-release，逐类执行）**：
位姿-重投影一致性；可见性矩阵满足类型约束（T3 背向实体≥2、T4 对视对存在且焦点全可见、
T6 房间专属锚≥2/房间、T8 遮挡判定可复算）；T2 zero 档真零共视；split 继承无违例。

**人工抽检**：每类 5 条轨迹 preview 目检（取景合理、无穿模、无室外、焦点物体构图正常）。

**整体验收**：P0+P1 完成后，QA 编译器 v2 能从每类轨迹产出其对应题族且通过
《QA编排格式与泄漏控制_v1》§3 的四项泄漏机检。

## 6. 论文方法学段落映射（写作提示）

采集章节按此结构叙述：四轴原理（§0 表）→ 类型设计（§2 各类"四轴坐标+能力假设"两行）→
质量门与失败保留政策（§0.5、§5）→ 数据统计表（§3 实测值替换估算值）。
每类轨迹在论文中的一句话模板："T_k 将相机采样约束在〈四轴坐标〉，使〈能力〉成为
回答其题族的必要条件，其真值由〈模拟器通道〉直接给出。"
