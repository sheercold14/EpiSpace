## 1. 五个能力的轨迹剧本设计

统一记法:每个剧本按框架五原则(R1 唯一路径 / R2 路径可走通 /
R3 其余平凡化 / R4 裕度可判定 / R5 旋钮=计算规模)给出:拍法、
成题条款、答案模式、变体预期、旋钮。所有金标由编译器从掩码/位姿
真值重算,变体金标由重跑同一编译器产生——这两条是既有制度,下不
重复。

### 1.1 基元 C(路径积分)+ 组合一(自运动更新)——已有,只列增量

现有 T1(walk_and_turn)承载四道题的诊断梯,已闭环。增量按专文
§6 的依赖序:

1. **答案偏科修复**(左 53/右 9):转弯方向抛硬币 + 终点环顾方向
   概率校准;验收线左右各≥25%、back≥15%(待拍板);
2. **T2 纯旋转**(stand_and_turn):站定看目标→原地转身超出视野→
   提问。只考旋转更新,平移为零。新增条款:位移≈0(上限如 0.1 m);
   指回起点题因"起点距终点≥1 m"条款自动不出——条款自筛,不需
   手工指定题型搭配;
3. **T3 纯平移**(walk_straight_past):目标在侧前方→直线走过不
   转头→提问。只考平移更新。净转向题因"|净转角|≥15°"自动不出;
4. **T4 多段转向**:T1 参数化,总转角拆 2–3 段,段间直行。旋钮
   "转向段数"由此激活;
5. **T5 遮挡消失**:目标仍在视锥内但被高障碍挡住。前置改动:遮挡
   判定从标签白名单(`behavior.py:43` 的 walls/pillar)改为高度规则
   (顶面高于相机 1.5 m 即遮挡物);需多房间场景。价值:补出 front
   类答案,拆穿"看不见=在身后"的捷径。

T2/T3 的存在理由是 Rieser(1989)人类分离签名——旋转后更新费力、
平移后接近自动;模型是否同构,只有拆开拍才可测。

### 1.2 基元 A(参考系变换)——环视剧本 + 想象位姿

**测什么**:把空间关系从实际视点换算到指定视点。按框架,证据必须
全程可见、无记忆负担,失败才能唯一归因到"变换"这一步(C2)。

**拍法 `survey`(新 motif)**:在场景内选一个视野良好的站位
(或两三个近距站位),原地缓慢环顾(限速≤40°/帧,与追踪条款一致),
使锚点 P(如门口)、朝向参照 Q(如床)、目标 X(如衣柜)各有若干帧
清晰可见(掩码像素≥阈值)。不需要长距离行走——行走引入的自运动
成分正是要平凡化掉的(R3)。

**题面**(题型5,两档):

- 深档:"若你站在{P}处、面向{Q},{X}在你的左边还是右边?"
  选项 left/right/front/back/无法判断;
- 浅档:"若你站在{P}处、面向{Q},能不能看见{X}?"选项 能/不能/
  无法判断。浅档可渲染验证:把想象位姿交给模拟器补渲一帧,用掩码
  核对几何金标——这是 A 家族特有的权威复核通道。

**成题条款**:

- `all_landmarks_visible`(新谓词):P、Q、X 各自的清晰可见帧数
  ≥下限(compile 阶段按掩码重判,on_violation=abstain——删掉目击
  帧即证据被毁,构造性产生弃答金标);
- P、Q、X 指称唯一(slotting 既有 ambiguous_referent 机制);
- 想象位姿可构造:yaw = atan2(Q−P),P 与 Q 距离≥下限(太近则
  朝向不稳定,属出包线 invalid);
- 扇区裕度≥15°(复用 sector_margin_ge 的构造位姿版)。

**答案模式 `imagined_sector` / `imagined_visibility`**(新):构造
位姿(P 的地面坐标 + 人眼高 + 面向 Q 的 yaw)× X 坐标 → 方位角 →
四扇区;浅档用 GeometrySceneView 的视锥+射线遮挡判可见,可渲染
复核。

**变体预期**(签名矩阵第一行):帧序置换→**不变**(证据静态,
这与 C/组合一的"置换→弃答"构成判别对);删目击帧(删含 P 或 X
的帧)→弃答;删冗余→不变;延迟→不变;**换视点→协变**——同一
环视录像上把想象视点转 0°/45°/90°/135°/180°,产出角度—误差曲线。

**旋钮**:实际视点与想象视点的 yaw 夹角(协变曲线的 x 轴)。这是
A 作为"变换引擎"的心理物理刻度,也是迁移预测的测点。

### 1.3 基元 B(对应锚定)——双胞胎剧本(排最后)

**测什么**:外观零判别力(同资产双实例)时,凭时空连续性维持实例
身份。R1 的落点:两实例必须同款同材质,让"看外观认"这条旁路彻底
失效,只剩连续性一条路。

**前置:场景编辑管线**(OminiGibson 侧,契约③):以编辑配方
(edit recipe)在既有场景中复制目标资产为 2–4 个实例、指定摆放
位姿,产出新场景 + 新 scene_ir + twin 分组标注(twin_group 字段:
同组实例的 entity id 列表)。EpiSpace 零模拟器依赖的原则不变——
它只消费带 twin 标注的 scene_ir 与渲染 bundle。摆放约束:两实例
距离≥下限(如 2 m)、不同房间/分区优先,保证轨迹上"看见其一时
看不见其二"可构造。

**拍法 `revisit`(新 motif)**:看见实例 i(在某地标旁)→ 移动
(逐帧可追踪,途中该组全部实例均不可见的间隔段)→ 再看见同组的
某实例 j → 提问。canonical 分两支:j=i(same)与 j≠i(different),
生成时各半。

**题面**(题型9,两问):

- 同一性:"现在看到的这把{类别},是不是你先前在{地标}旁看到的
  那把?"选项 是/不是/无法判断;
- 计数:"这段行走中,你一共见过几把{类别}?"选项 1/2/3/无法判断。

**金标**:实例掩码身份。同一性 = 前后两段目击的 runtime instance id
是否相同;计数 = 出现过的同组 runtime id 数。全部可从 bundle 逐
字节复算,不涉人工。

**成题条款**:

- `twin_indistinguishable`:同组实例同资产(scene_ir 校验,
  invalid);
- `episodes_separated`:两段目击之间存在≥N 帧的全组不可见间隔
  (abstain——正是这段间隔迫使身份靠连续性维持);
- trackable(复用):帧间限速保证连续性线索本身可用(R2——
  不给连续性线索又问身份,是不公平题);
- 计数版另加:同组每个实例的掩码首现帧存在(未全部见过→金标=
  弃答,构造性)。

**变体预期**:帧序置换→**弃答**(连续性即证据,置换毁证据——
与 C 同列,属"算出来的"一侧);删目击帧(删其中一段目击)→弃答;
删冗余→不变;延迟→不变。此行为框架签名矩阵新增行,须写入 spec
的 variant_expectations 并由编译器核对。

**旋钮**:重复实例数(2/3/4)。

**为什么排最后**:唯一依赖仓外新管线(场景编辑)的能力,且组合二
不依赖它的实现(组合二用类别唯一的地标即可)。框架 §8 也如此排序。

### 1.4 组合二(跨视图绑定)——永不同框剧本

**测什么**:经共同地标拼合从未同框二物的关系,= 读出 + B(实例
身份,此处用类别唯一物降为平凡)+ A(参考系变换)+ 关系复合。
关系复合不设基元(违 C2),经锚链长度旋钮以协变曲线测量。

**拍法 `visit_landmarks`(新 motif)**:waypoint 巡访。给定目标对
(X, Y)与锚链 L1…Lk,轨迹依次经过若干观察站:站 1 看见 X 与 L1
同框,站 2 看见 L1 与 L2 同框……站 k+1 看见 Lk 与 Y 同框;全程
X 与 Y 永不同框。骨架复用 walk_and_turn 的占据栅格 + A* 段间导航,
新增的是"多站位序列 + 每站可见性目标"的搜索层。需要多房间或大
场景(与 T5 共用场景核查工作)。

**核心条款 `never_covisible(X, Y)`**(新谓词):所有帧中不存在
X 与 Y 掩码像素同时≥可见阈值的帧。搜索期用几何视锥预筛,compile
期以掩码权威重判——这是本剧本的存在性条款,靠它保证"直接读关系"
的旁路被堵死(R1),关系复合被迫发生。配套 `chain_connected`:
链上每段共见(X–L1、L1–L2、…、Lk–Y)各有≥N 帧双方同框清晰可见
(abstain——删任一段即断链,构造性弃答)。

**题面**(题型6 主打 + 题型7 副题):

- 物物关系:"{X}在{Y}的哪一侧?"参考系约定待拍板(§5 决策 2),
  建议用 Y 的内在朝向(scene_ir 有家具朝向;"床头柜在床的左侧"
  类表述),避免引入额外的观察者视点转换;
- 远近比较(副题):"{X}和{Y},哪个离{L}更近?"距离比≥阈值
  方成题——无参考系歧义,作为组合二的保底题型。

**金标**:双物体几何(scene_ir 坐标 + 朝向),阈值化留裕度。

**变体预期**(签名矩阵既有行):帧序置换→**不变**(任意合法序
都能建链——与组合一的"置换→弃答"构成组合层的判别对);删目击帧
(删某段共见)→弃答(断链);删冗余→不变;延迟→不变;**换锚→
协变**(锚链长度 1/2/3 的误差曲线)。

**旋钮**:锚链长度 k(关系复合步数的直接刻度)。

### 1.5 元能力(证据校准)——两条腿

**第一条腿(已在制度里)**:每个家族的弃答变体。删目击/断链后
金标构造性地变为"无法判断",测模型能否在证据被毁时收手。此腿
随各家族自动扩展,无需单独开发。

**第二条腿(题型10,存在与充分性,待做)**:"这套房里有没有
{类别}?"选项 有/没有/无法判断。金标三分:

- 场景清单有该类且被看见(掩码首现存在)→ 有;
- 场景清单无该类且视锥覆盖率≥阈值 → 没有;
- 覆盖率不足(存在足以容纳该类物体的未覆盖区域)→ 金标=弃答
  (构造性:弃答不是"模型不会",是"证据客观不够")。

**覆盖率计算**(新模块):复用 motifs 的 5 cm 占据栅格,把每帧
视锥(含 GeometrySceneView 既有的射线遮挡截断)光栅化,累计标记
已覆盖自由格;覆盖率 = 已覆盖/全部自由格。阈值与档位进
standards(升版)。剧本上不需要新拍法——任何家族的轨迹都可附
挂题型10,但要控制覆盖率落在目标档位,需在生成端加覆盖率导向的
轨迹筛选(接受-拒绝即可,不必新 motif)。

**泛化轴**:覆盖率档;留出的全新删除模式(held-out)——评测时
用训练/校准阶段没见过的删帧方式构造弃答,防模型背"哪种手术=
该弃答"的表面规律。

## 2. 题型安排:10 题型 × 5 类轨迹

同一条轨迹承载多道题(组打包 `--group` 已支持,机会性跳过已实现),
题型与轨迹的搭配由各题成题条款自动筛,不手工指定:

| 轨迹类型 | motif | 承载题型(角色) | 家族归属 |
|---|---|---|---|
| 自运动 T1–T5 | walk_and_turn 及其变种 | #2 画面侧(检查)→ #3 净转向(C 主打)→ #4 指回起点(探针)→ #1 自我方向(组合一主打) | C + 组合一,四级诊断梯 |
| 环视 | survey | #5 想象视点(A 主打);#6 物物关系当场版、#7 远近当场版(陪衬);#8 出现先后(检查) | 基元 A |
| 地标巡访 | visit_landmarks | #6 物物关系永不同框版(主打)、#7 远近(副题)、#8 出现先后(检查) | 组合二 |
| 双胞胎重访 | revisit | #9 实例同一/计数(B 主打);#2 画面侧(检查) | 基元 B |
| 任意(附挂) | — | #10 存在与充分性(元主打);弃答变体寄生全部家族 | 元能力 |

诊断梯是安排的骨架:自运动轨迹上 #2→#3→#4→#1 逐级加一个环节
(读出→积分→积分+变换→全流水线),首个坍塌层级即失败定位。
陪衬题(#6/#7 当场版)的作用是给组合二提供"同框即可读"的对照:
当场版对、永不同框版错,失败归因到绑定而非关系概念本身。

操纵检查(#2、#8)每家族自带、质检不计分;挂科模型的同家族主打
题标记"读出污染"剔除——此机制已实现于组打包的角色字段
(primary/probe/check),新家族沿用。

## 3. 代码工程设计

### 3.1 先修债务(阻塞扩展,新能力动工前清掉)

现状核查发现的问题按是否阻塞排序:

1. **`generate._provisional_answer` 硬编码四扇区**
   (generate.py:127-139):不看 AnswerSpec.mode,凡新答案模式驱动
   生成都会在编译期恒定触发 sector_disagreement 阻断。修法:改为
   经 answers 注册表分发,用 GeometrySceneView 算几何临时答案——
   与编译器同一套代码,消灭第二处答案逻辑;
2. **variants 的 t_gone 兜底魔法数**(variants.py:106,156):
   permute/delay 对无 t_gone 的 spec 实际作用于 [1, t_q),属未声明
   行为。修法:spec 新增声明字段(如 `intervention_window`,帧范围
   表达式,复用 checker 的区间语言),算子只认声明;
3. **通行条款只挂在 SELF_MOTION**(library.py:31-41):其余 spec
   独立驱动搜索会产出穿家具轨迹。修法:凡含 motif 的 spec 由
   library 层强制附加 poses_clear/path_clear(search_only)——
   加一个 spec 构造辅助函数,新家族默认带通行;
4. **label 校验与打包只看 templates[0]**(compiler.py:288,
   family.py:182):基元 A 深/浅两档、B 同一/计数两问都需要多模板,
   动工 A 之前修;
5. 非阻塞顺手项:plan/certificate/question_group 三个 schema 注册
   进 contracts;帧号泄漏正则补英文写法("frame 3");死代码
   `rotated_rect_penetration_depth` 删除;`STD_V1` 常量名改为
   `STD_CURRENT` 类中性名(其 version 已是 std.v4,名实不符);
   STATUS.md/CHANGELOG.md 补 scriptgen 条目。

### 3.2 各层新增(按既有分层,每项落在现成注册表里)

引擎的扩展点设计已经就位(motif 注册表、答案模式注册表、谓词单点、
声明式 spec),新能力全部是"填内容",不动架构:

- **standards.py**:新阈值一律升版 std.v5——A 的视点夹角档、最小
  P–Q 距离;B 的实例间距、目击间隔帧数;组合二的共见帧数下限、
  距离比阈值;元的覆盖率档。遮挡判定改高度规则的 1.5 m 相机高
  阈值也进 standards(它是判定阈值,非生成参数);
- **geometry.py**:构造位姿(点 + 面向点 → yaw)辅助;扇形视锥
  光栅化(覆盖率用);
- **predicates.py**:`all_landmarks_visible`、`imagined_pose_valid`、
  `never_covisible`、`chain_connected`、`twin_indistinguishable`、
  `episodes_separated`、`coverage_ratio_ge`、`displacement_below`
  (T2 用)。全部维持"返回 Verdict(holds, witness)"契约,witness
  记录数值证据;
- **answers.py**:`imagined_sector`、`imagined_visibility`、
  `same_instance`、`instance_count`、`pair_relation`、`closer_of`、
  `existence_sufficiency` 七个新模式,注册制不变;
- **motifs.py**:`stand_and_turn`、`walk_straight_past`、`survey`、
  `visit_landmarks`、`revisit` 五个新 motif + walk_and_turn 的偏科

## 4. 各能力如何相互配合

配合不是靠共享代码,是靠四个结构性设计:

1. **共享变换引擎 A(迁移预测的载体)**:组合一 = 读出+C+A
   (锚=自身),组合二 = 读出+B+A(锚=地标)。两组合只换输入
   通道与锚,变换步同源。由此可预注册:只训组合一,若模型有统一
   空间状态(H2),组合二中依赖 A 的成分零样本受益;H0/H1 均不
   预测此迁移。工程含义:A 家族的角度—误差曲线必须先测出来,
   作为"变换成分"的独立标定,组合的成绩才能分解;
2. **诊断梯(共享轨迹的纵向切片)**:同一条自运动轨迹出 #2→#3→
   #4→#1 四道题,逐级加环节;基元 C 的净转向题就是组合一的中间
   截面。组打包共享媒体已实现,新子型(T2–T5)自动继承此结构。
   组合二同理有自己的横向对照:同框当场版(#6 陪衬)对、永不同框
   版错 → 失败在绑定步;
3. **置换分化(算 vs 翻的全局判别)**:同一置换手术下,C/组合一/B
   弃答(序即证据),A/组合二/检查题不变(证据静态或任意合法序)。
   这个跨家族的分化模式只有把五个能力都测齐才成立——单看任一家族
   都解释不了;它是签名矩阵的主对角结构,也是 H0/H1/H2 判别的
   核心证据。工程上每格由 spec 声明 + FamilyMismatch 钉住;
4. **操纵检查与元能力(横向寄生)**:读出检查(#2/#8)每家族
   自带,挂科即标记读出污染剔除,保证五个能力的成绩可比;弃答
   变体寄生全部家族,题型10 附挂任意轨迹——校准是对所有家族
   统一测的第三维,不是第六个并列家族。
