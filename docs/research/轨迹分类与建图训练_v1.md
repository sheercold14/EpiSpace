# Part 1 轨迹分类：从第一性原理到采集规范

## 1.0 第一性原理：轨迹 = 信息结构的采样策略

一条轨迹本质是在 SE(3)×时间 上的采样策略。它诱导出的**信息结构**决定了哪些空间能力
可以被出题考察。四个控制轴：

| 控制轴 | 两端 | 决定的能力 |
|---|---|---|
| A. 基线类型 | 平移（有视差→深度可推） vs 纯旋转（无视差） | 深度/尺度 vs 朝向/全景整合 |
| B. 视图重叠度 | 稠密链（注册容易）→ 稀疏宽基线 → 零重叠 | 跨视图注册的难度阶梯 |
| C. 覆盖与揭示顺序 | 全覆盖 vs 部分覆盖；先看 vs 后看 vs 永不看 | 认知状态（known/seen-not-current/unknown） |
| D. 参照结构 | 场景中心 vs 物体中心 vs 观察者锚定 | 地图构建 vs 物体3D理解 vs 视角采择 |

市面 benchmark 在这四轴上的落点（我们要全覆盖）：

- **VSI-Bench**：A平移+B稠密+C全覆盖（视频漫游）
- **MindCube**：三种设定——Rotation（原地旋转）/ Among（穿行于物体之间）/ Around（绕焦点物体）；B稀疏（2–4视图）
- **MMSI-Bench**：B稀疏到零重叠的任意图对，相机-相机关系
- **BLINK / 两视图对应**：B可控重叠的双视图
- **ViewSpatial**：D观察者锚定（站在某处朝某向）
- **3DSR / EmbSpatial**：单图 3D 关系（退化情形，T1 子集覆盖）

## 1.2 各类详细要求

### T1 覆盖漫游（现 M2 基线，保留）
- **采样**：房间实例分割内取端点（M2 教训：不許采到室外），人眼高度 1.4–1.6m，
  连续无碰撞路径，按房间顺序，含 turnaround、revisit、终点回到起点（loop closure）。
- **质量门**：loop RGB PSNR ≥30dB；每视图可见核心实体 ≥3；整条轨迹观察实体 ≥15。
- **出题**：全能力基线 + 出现顺序题 + 记忆回溯题。
- **禁忌**：路径不得为任何问题定制（coverage-first；挑战视图按能力缺口补，不按题补）。

### T2 稀疏子采样（从 T1 派生，零渲染成本）
- **采样**：从 T1 的 11+ 视图中抽 k∈{2,3,4,5} 张，控制两个参数：
  相邻抽样视图的**共视实体数**（高/低/零三档）与**相对朝向差**（<45°/45–120°/>120°）。
- **约束**：每个子集标注共视图连通性——连通子集出"可答"题，刻意断开的子集出"弃答"题；
  同一子集生成"顺序打乱"变体（地图应与顺序无关）。
- **出题**：MindCube-Among 风格（有限视图心理建模）、MMSI 风格图对题。
- **要点**：这是**性价比最高的一类**——不需要新采集，编译器升级即可获得；
  训练时视图数随机化，消除"11 视图连续漫游"这根拐杖。

### T3 原地旋转站（需新采集）
- **采样**：每场景选 2–3 个站位（房间中央、走廊交叉口），相机位置固定，
  yaw 均匀扫 4–8 个朝向（90°/60°/45° 步进），pitch 固定；站位之间用 T1 路径连接可选。
- **约束**：纯旋转 = 零视差，深度类问题禁用；每站全景合并后可见实体 ≥8，
  且存在"只在背向朝向可见"的实体（否则"背后有什么"无意义）。
- **出题**：旋转顺序题（"右转90°后会看到什么"）、全景整合题（"这个房间一共有哪些家具"）、
  背后推理题（"你现在背对的方向有什么"）、朝向变换题。
- **真值**：每个朝向的可见集 + 站位全景可见集；旋转角度来自位姿真值。

### T4 物体环绕（需新采集 + 资产筛选）
- **采样**：选定焦点物体（或物体组），半径 1–3m 环绕采 6–12 视图，覆盖正面/侧面/背面，
  可变高度；**必须包含相对视角对**（相差约180°的两张）。
- **资产要求**（这类对资产最挑剔）：
  - 焦点物体必须**非旋转对称**（scene_ir 的 `symmetry_group` 过滤：对称物体不问朝向）；
  - 必须有可靠 `canonical_front`（沙发、电视、椅子、冰箱是好焦点；花瓶、圆桌不是）；
  - 物体背后要有**可辨识的背景内容**（贴墙物体的"背后场景"题自动降级为遮挡题）。
- **出题**：同一物体对面视角的同一性判断（"这两张图是同一把椅子吗，从哪两个方向拍的"）、
  物体朝向题（"沙发面向哪边"）、背后场景题（"从沙发背后看过去能看到什么"）、
  环绕顺序题（"按顺时针环绕排序这几张图"）。
- **真值**：相机-物体相对方位角逐视图记录；物体前向来自 canonical_front。

### T5 双视图对（从 T1/T3/T4 派生 + 少量专采）
- **采样**：三档共视度各占约1/3——高共视（≥5共同实体）、低共视（1–2个）、零共视；
  相对位姿分箱记录（平移距离 × 朝向差）。
- **出题**：相机间关系题（"第2张的拍摄者在第1张拍摄者的哪个方向"——MMSI 相机-相机类）、
  跨视图实体绑定题（"两张图里的桌子是同一张吗"）、零共视时的弃答题。
- **要点**：相机-相机关系是 MMSI 的特色题型，我们的位姿真值让它免标注。

### T6 跨房间桥接（T1 的约束加强版）
- **采样**：轨迹必须穿过 ≥2 个门洞、覆盖 ≥3 个房间；
  **每个房间必须存在专属锚定实体**（只在该房间的视图中可见）。
- **出题**：跨房间非共视关系题（我们的主实验轴）、房间拓扑题（"厨房和卧室隔着几个房间"）、
  路线题（"从沙发走到冰箱要经过哪些房间"，navmesh 真值）。
- **约束**：46 场景中 multi_room_rich 类（44个）天然支持；sparse 类跳过此类出题。

### T7 高度/俯仰变化（少量专采）
- **采样**：同一站位/短路径，三档高度（0.3m 宠物视角 / 1.5m 人眼 / 2.5m+俯视 30–60°）。
- **出题**：视点不变关系题（同一对物体在不同高度下关系不变——一致性 family）、
  俯视-平视对齐题（"俯视图中的哪个物体是平视图里的沙发"——直接服务建图接地）。
- **要点**：俯视视图是 cognitive map 的天然可视化，与 Part 2 的建图训练强耦合。

### T8 遮挡揭示（T1 路径规划时显式植入）
- **采样**：路径先经过"目标被大件遮挡"的视角，绕过遮挡物后揭示；
  遮挡帧与揭示帧（decisive frame）显式标注。
- **出题**：恒存题（"绕过隔断后，刚才看不到的那半边有什么"）、
  epistemic 转换题（揭示前问→必须弃答或说"被挡住"；揭示后同一问题→实答）；
  与 family 变体 `decisive_view_deleted` 组合成三重一致性。
- **真值**：逐帧可见性 + 遮挡关系来自 instance mask 与深度。

### T9 干预对（已有，接入即可）
- relation-flip 24 对 + model-swap 24 对已认证。出题：同轨迹同问题，答案必须翻转/不变
  （learning_signal 字段已给出）；直接编译为 RLVR consistency_group。

### T10 视角采择锚点（T1 附属渲染）
- **采样**：主轨迹外，在锚定实体位置渲染 held-out 目标视图（不进 write 前缀，仅验证用）。
- **约束**：锚点对（origin, facing）不得共线/重合；目标位姿必须可达。
- **出题**：P 原子题（"站在A面向B会看到什么"），答案由真实渲染验证——
  这是把 ViewSpatial 类题从"标注员想象"升级为"渲染器裁决"。

## 1.3 全局硬性要求（所有类共用）

1. 位姿/可见性/深度真值随每视图落盘（现 npz 格式已满足）；
2. 通道隔离沿用现契约（model_visible 只有 RGB）；
3. 每条轨迹带 `trajectory_class` 与逐视图 `role` 标签，进 trajectory_plan.json；
4. 低于可见像素阈值（128px）的实体不参与该视图出题；
5. 每类轨迹独立质量门，失败记录保留在 manifest（不许静默丢弃）；
6. 采集优先级：**T2/T5（免费派生）→ T3/T4（新采集、benchmark 缺口最大）→ T7/T8（增强）**。

# Part 2 建图能力怎么训进模型

## 2.0 MindCube 的结论与我们的差异定位

MindCube 的核心发现（37.8% 基线 → map-then-reason SFT 60.8% → +RL 70.7%）：

1. **地图作为输入（被动喂图）几乎无用**；模型必须**自己生成**地图再推理；
2. 单独生成地图不推理、或只推理不建图，收益都小；**联合"先图后推"最大**；
3. 地图格式：10×10 俯视网格（[0,0] 左上），objects 位置 + facing（上/右/下/左/内/外）+
   augmented 版加相机位姿；
4. RL 在结构化思维注入后再做，收益叠加。

这验证了我们的核心假设（外化中间状态可训练），但 MindCube 的方案有四个可改进点，
恰好是我们模拟器管线的强项：

| MindCube 的局限 | 我们的升级 |
|---|---|
| 地图是**问题相关子集**（只放与题有关的物体）→ 仍是"为题建图" | **query-agnostic 地图**：包含全部已观察核心实体（契约 §3 的复用压力） |
| 地图**一次性生成**（看完所有图一口气建） | **增量建图**：逐批观察后更新，问题块前 COMMIT（write-then-read） |
| 单一 JSON 格式 → 格式锁死风险 | **双表面**：同一地图既有自然语言版也有 JSON 版 |
| 训练时地图有 GT，但 RL 奖励主要看答案 | **格级可验证 + 图-答一致性执行器**（见 2.2） |

## 2.1 地图 schema（对齐 MindCube 便于对比，按契约扩展）

```json
{
  "frame": "scene_bbox_topdown",          // 俯视，场景包围盒归一化
  "grid": [10, 10],                        // 兼容 MindCube；另存 0.5m 米制 bin
  "entities": [
    {"name": "冰箱", "cell": [7, 1], "bin_0p5m": [0, 6],
     "facing": "down",                    // 仅非对称物体输出（symmetry_group 过滤）
     "status": "seen_not_current",        // visible | seen_not_current | unknown
     "evidence_views": [1, 2, 3]}
  ],
  "cameras": [                              // augmented 版：相机轨迹也入图
    {"view": 1, "cell": [5, 8], "facing": "up"}
  ]
}
```

相对 MindCube 的三个字段级增强：`status`（认知状态——我们的 epistemic 特色）、
`evidence_views`（证据溯源）、米制 bin（真实尺度，服务度量题）。

## 2.2 训练机制：五件套

**① SFT 三形态配比**（对每道"DAG 含 B/F* 的题"，即真正需要建图的题）：

- 30% 直答（防话痨、保直觉）；
- 50% **最小充分子图推理**：思考中只外化**本题推理路径上的实体**（DAG 的证据闭包：
  相关实体 + 一个坐标锚），不外化全图——"冰箱在厨房东北角、电视在客厅南侧、
  两区隔约5米"三句话就是这道题的最优回路；数值全部来自 GT；
  **充分性可机检**：把模型外化的子图喂给查询执行器，若不足以推出答案则该 trace
  标记不充分（S-Agent 消融同向证据：原始 3D 证据整体灌入无效，
  经语义过滤+关系特定计算的证据才有效）；
- 20% **JSON 图**（指令条件化）：仅当 prompt 显式要求输出地图时给全图。

**query-agnostic 与最小外化不矛盾——它们分属 write 和 read 两相**：
query-agnostic 约束的是**内部必须保留什么**（观察时问题未知，无法按题过滤感知），
最小充分子图约束的是**答题时外化什么**。完整地图的训练压力不来自"每答必画全图"，
而来自三处：(a) 同一 episode 的 12–24 个 read 的最小子图**并集≈全图**，内部表征
不完整就总有题答错；(b) 记忆/延迟揭示类问题在观察时不可预知，按题过滤感知必然失败；
(c) 低频的专职 state-commit 任务（structured_aux 与 belief 更新 turn）是唯一
外化全图的地方。外化地图的规模跟着**问题**走，不跟着场景走——
稀疏视图（MindCube 2–4 图）下全图与子图本就几乎重合，冗余问题主要发生在
11 视图 50 实体的大场景，此原则正是为它设的。

单视图可答的题**不配建图输出**——教"何时建图"，不教"总是建图"（MindCube 没做这层
调用策略，我们必须做，否则通用 QA 会被地图污染）。RLVR 阶段加轻量 token 成本项，
让模型自己发现更省的回路，而不是模仿我们的规范路径。

**② 增量建图入对话**：episodic_dialogue 中每批图像后插入简短 belief 更新 turn
（"新看到了X、Y；Z 离开视野"），问题块前一个 COMMIT turn（完整地图，双表面之一）。
这直接复用契约的 ΔS 监督，把"一次性建图"升级为"随观察维护"。

**③ 格级奖励（RLVR）**：模型输出的地图逐实体判分——entity binding F1、
position bin 误差、facing 准确率、status 准确率。模拟器真值让每个格子可判。

**④ 图-答一致性执行器**（我们独有的杀手锏）：把**模型自己输出的地图**喂给查询执行器，
在它的地图上执行本题的程序，检查推出的答案与模型给出的答案是否一致。
"图上明明画着电视在冰箱南边，嘴上却说北边" → 罚。这治的正是 MindCube 观察到的
"图归图、答归答"的脱节——他们只能靠联合训练间接缓解，我们能显式执行检查。

**⑤ 脚手架淡出（scaffold fading）**：训练后期对 30–50% 的建图样本把地图段从监督中
mask 掉、只监督最终答案（地图仍在 rollout 中允许出现但不强制）。目的：外显地图是
训练轮的辅助轮，最终能力要内化进激活——推理时对简单题不必付地图的 token 成本。
验证指标：state-only 与 full-context 的差距（契约 §10 的 state sufficiency gap）
+ 淡出后直答准确率是否保持。

## 2.3 与家族变体的耦合（建图正确性的因果验证）

- `legal_set_shuffle`：乱序观察 → **地图必须不变**（图级一致性奖励）；
- `decisive_view_deleted`：删证据 → 地图上对应实体必须变 `unknown`，
  依赖它的答案必须弃答；
- T9 干预对：单物体移动 → 地图上**只有该实体的格子变**，其余格子不许动
  （反事实局部性——防止模型每次重新胡编整张图）。

## 2.4 预期与证伪

- 预期：MindCube 榜（考的就是有限视图建图）收益最大；参照其 +23pp（SFT）量级设定
  内部基线，但我们的主张不是复现他们，而是验证**增量+可验证+双表面**的建图训练
  在保持通用 QA 的前提下（守门 ≤1pp）优于一次性 JSON 建图；
- 证伪条件：若图-答一致性执行器的通过率提升但答案准确率不提升，
  说明地图是"表演性"的（学会画图但不用图推理）——此时优先加大 ④ 的奖励权重
  而不是加数据；若 fading 后直答大幅回落，说明能力未内化，延长 ②③ 阶段。
