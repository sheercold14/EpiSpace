# Scriptgen QA 案例评审与生成策略复盘 v1

日期：2026-08-10

数据集：`scriptgen_qa_v1`

网页：http://192.168.2.78:8022/

评测模型：`SenseNova-SI-1.5-InternVL3-8B`，prompt `scriptgen-qa-eval.v2`

## 结论

这批数据能够评测一组定义明确、可由编译器验证的空间心智能力：第一人称自运动状态更新、净转向、指回起点、历史画面侧、假想参照系变换、假想视野判断，以及跨视图对象关系。它还加入了两个容易被普通空间问答忽略的维度：证据不足时是否弃答，以及共享轨迹历史时能否随新证据更新答案。

当前结果同时说明，它还不能直接作为对外宣称“综合空间智能”的最终 benchmark。主要原因不是金标不稳定，而是数据规模、标签捷径和评测结构仍有限：当前只有 24 个场景、50 条贡献轨迹，尚未做 scene/trajectory/family 聚类切分；P3 的无视觉准确率高于多模态；P2/P3 streaming 固定为“第一轮弃答、第二轮可回答”，训练后可能形成轮次捷径；所有 streaming 记录的全 turn 正确率均为 0%。这些问题应作为下一轮扩量和对照实验的依据，不能通过修改金标或删除模型答错的样本解决。

从训练角度，这批数据有合理机制支持空间泛化，但目前没有证据证明已经提升泛化。支持机制来自同一空间事实的证据干预、同一轨迹的递增前缀、跨题型共享视觉历史和编译器 certificate；是否真正转化为泛化能力，必须通过聚类无泄漏切分、训练消融和 held-out composition 实验验证。

## 如何对照网页 review

网页左侧支持按格式、批次、P1/P2/P3、题型、变体和 case 分类筛选。下表中的 `record_id` 可直接粘贴到搜索框。建议按以下顺序查看：

1. 先看 `eligible`，确认图像是否确实提供了无视觉条件没有的信息。
2. 再看 `shortcut_risk`，检查问题措辞、标签分布或固定答案位置是否能绕过图像。
3. 查看 `drop_key` 和 streaming 的第一轮，判断“无法判断”是否符合肉眼可见的证据充分性。
4. 最后看 `valid_hard`，区分真正的模型推理失败、输出格式失败和可能需要人工复核的题目。

`eligible`、`shortcut_risk` 和 `valid_hard` 都是相对于当前冻结模型的诊断分类，不是数据本身永久不变的质量标签。换模型后分类可能改变；compiler certificate 和金标不会因此改变。

### P1：视觉贡献存在，但不是所有自运动题都成立

P1 raw 的多模态准确率为 44.6%，无视觉为 34.7%。净转向为 61.7%/40.0%，历史画面侧为 60.0%/30.0%，说明部分题目确实要求读取时序图像。`raw-50d656...` 和 `raw-de602...` 是优先确认视觉合理性的正例。

指回起点只有 11.1%/33.3%，自运动方向更新合计为 12.0%/12.0%。`raw-dbc5...` 中模型把 `back` 答成 `front`，无视觉答 `right`；这更像没有形成稳定的自位置表征，而不是输出格式问题。净转角幅度为 52.9%/52.9%，没有观察到总体视觉增益，需检查 90° 标签分布、轨迹运动幅度以及模型是否使用固定答案倾向。

### P2：基准变换可测，角度组合和可见性仍很弱

P2 假想方向合计为 22.2%/18.4%，其中不带额外 yaw 的基准变换达到 64.0%/32.0%，说明 `raw-0916...` 这类题可以测到视觉支持的参照系变换。加入 45°、90°、135°、180° 后准确率显著下降，`raw-d82e...` 是典型案例。

P2 可见性合计为 15.4%/17.6%，无视觉反而略高；其标签分布为 `not_visible=312`、`visible=88`、`无法判断=100`。因此可见性题当前同时混合了几何变换难度和标签不平衡，不能只用总体准确率判断模型的空间想象能力。下一轮应在 compiler 约束内增加 `visible` 样本，并按角度和标签做平衡报告。

### P3：题目机制有效，但当前规模和捷径风险不足以支持强结论

P3 raw 只有 100 条。跨视图距离比较为 61.8%/65.5%，跨视图对象关系为 28.9%/53.3%；P3 共 60 条 `shortcut_risk`、37 条 `valid_hard`，只有 3 条 `eligible`。`raw-e12e...` 展示了无视觉也答对的问题，说明当前模型可能利用候选位置、实体共现或标签先验。

`raw-6566...` 的多模态回答是 `<answer>fridge</answer>`。问题已声明 `fridge` 对应第二个候选，因此语义评测映射为 `second`，但 strict-format 仍为失败。该 case 不应被删除：它证明题目语义可以被模型理解，同时揭示了输出协议遵从问题。

## 逐百条反思汇总

| 数据 | 批次 | 记录数 | eligible / shortcut / valid-hard | 策略状态 |
|---|---:|---:|---:|---|
| raw | 14 | 1,394 | 106 / 326 / 962 | 12 个 `keep`，raw-0004、raw-0006 为 `review` |
| streaming | 3 | 238 | 0 / 0 / 238 | 3 个 `keep`；`keep` 只表示没有协议故障或达到捷径阈值，不表示模型通过 |

每个批次最多 100 条，并在 P1/P2/P3、capability、变体和标签之间分层交错。逐批 JSON 位于 `outputs/scriptgen_qa_v1/batch_reflections/`，网页顶部“批次审计”汇总了每批的模型条件、能力覆盖、泛化判断、策略动作和代表 case。

raw-0004 含 35 条 shortcut-risk，多模态/无视觉准确率为 33%/35%；raw-0006 含 45 条 shortcut-risk，多模态/无视觉为 40%/45%。两批都需要检查 P3 closer、P2 visibility 和标签分布，但 compiler 金标保持不变。其他批次的 `keep` 表示维持冻结题面和证据调度，不代表其中没有 hard case。

这些反思是对已经冻结的 v1 数据做 post-hoc 分批审计，不是每完成 100 条就修改生成器、再生成下一批。这样做避免根据单一模型表现追改金标，但也意味着全量结果提出的标签平衡和反捷径策略尚未作用于 v1；它们必须进入新的 policy/version，再用消融实验验证。

## 这批数据能否评测空间心智能力

### 能够评测的部分

1. **可执行的空间状态更新。** 每道题的 label、证据充分性和关键 witness 来自 compiler，而不是人工凭印象标注。P1 要求从连续第一人称观察更新自身运动状态，P2 要求执行显式参照系变换，P3 要求跨视图保持对象身份。
2. **证据必要性。** `drop_key` 和 streaming 的 `abstain→answerable` 对同一空间程序做干预，能够区分“模型猜中答案”和“模型知道答案由哪些证据支持”。当前 `drop_key` 两个条件准确率均为 0%，说明这个维度确实比普通多选题更难。
3. **共享历史下的增量推理。** streaming 同时给出 teacher-forced 和 free-running 条件，可分离当前轮推理错误与历史错误累积。多模态 teacher-forced/free-running turn 准确率为 19.5%/18.5%，格式率为 69.1%/41.2%，历史主要加剧了输出格式退化。
4. **视觉依赖诊断。** raw 多模态/无视觉为 26.3%/24.5%，但分层后 P1 为 44.6%/34.7%，P3 为 47.0%/60.0%。vision-free 对照避免把全局均值误解成一致的视觉能力。

### 当前不能支持的结论

1. 不能代表全部 spatial intelligence。数据没有测量连续度量重建、自由导航规划、主动视点选择、动态物体交互或开放词汇空间描述。
2. 不能证明跨场景泛化。当前仍是 `development_pool`，没有正式 train/test split；同一 scene、trajectory 或 family 的变体若被随机拆分，会产生严重泄漏。
3. 不能用 SenseNova 的单模型分类决定样本有效性。`valid_hard` 可能是真难题，也可能包含模型不熟悉的格式；`shortcut_risk` 是风险信号，不是自动删除条件。
4. 不能把 P3 的高无视觉分数解释为跨视图能力。它反而表明当前 P3 覆盖和标签对照不足。
5. 不能把最终 turn 正确当作 streaming 成功。四个条件的 all-turn correctness 和 evidence-update success 均为 0%。

因此，这批数据适合作为可执行、可诊断的开发集和训练候选池；在完成聚类切分、标签对称化和多模型复核前，不适合作为最终对外 benchmark。

## 这些数据是否可能提升空间泛化

可能，但结论依赖以下因果链条，而不是依赖数据量本身：

1. `canonical` 给出基础空间程序和正常证据。
2. `drop_filler`、`delay` 和安全 `permute` 要求同一几何事实对无关帧、延迟和允许的顺序变化保持不变，提供不变性监督。
3. `drop_key` 把同一家族从具体方向改为“无法判断”，要求模型学习证据必要性，而不是记忆问题到标签的映射。
4. streaming 用同一轨迹的不同前缀监督状态更新；teacher-forced 训练当前轮能力，free-running 评测历史误差传播。
5. 多个 P1 题在同一轨迹历史中出现，迫使模型复用自运动表征，而不是为每个题型重新读取独立样本。
6. 如果后续按 scene/trajectory/family 聚类切分，训练收益只能通过未见场景、未见轨迹和未见组合上的表现获得，才有资格称为空间泛化。

建议用四组消融验证这条链条：A 只训练 raw canonical；B 加入四类证据变体；C 再加入 streaming；D 加入下一轮反捷径和平衡样本。评测至少报告 capability macro、family macro、trajectory macro、family all-variant correctness、vision contribution、drop-key abstention、evidence-update success，以及语义准确率和 strict-format 两套指标。只有 B/C/D 在 held-out scene 和 held-out composition 上稳定优于 A，才能说明这些监督提高了空间泛化。

## QA 生成策略的迭代与下一步

### 已完成并应保持冻结的迭代

1. **删除单帧 P1。** 候选策略曾允许 prefix=1 的净转角幅度题；几何约定可以给出答案，但单张图像没有可观察的运动变化。最终要求 P1 `prefix_length >= 2`，没有改金标。
2. **分离语义与格式。** 模型可能输出 `fridge` 而不是 `second`。v2 解析器在问题能唯一建立实体与选项映射时计为语义正确，同时保留 strict-format 失败。
3. **彻底隔离 oracle。** streaming `input_sha256` 不再纳入 `status`、`certificate_sha256` 或答案摘要；改变答案和 certificate 时，answer-hidden 输入 hash 必须不变。
4. **模型不能改金标。** 1,200 条 `valid_hard` 保留 compiler 金标；模型失败只影响诊断分类。

### 根据全量结果建议的下一轮策略

1. **先冻结 v1，不回填本轮结果。** 当前数据、金标和评测结果作为可复现基线；改进以新的 policy/version 生成，不覆盖 v1。
2. **对称化 P3 候选顺序。** 为同一 certified 几何关系生成实体顺序互换的兄弟题，并同步变换 `first/second`，检查模型是否仍依赖答案位置。
3. **平衡 P2 可见性标签。** 在不放宽几何 margin 的前提下补充 `visible`，按 yaw×label 分层采样；不能为平衡手改现有金标。
4. **打破 streaming 的固定轮次模式。** P2/P3 除 `abstain→answerable` 外，增加经 compiler 认证的 `abstain→abstain`、`answerable→answerable` 和答案变化序列，随机化提问时机，避免模型学到“第一轮弃答、第二轮作答”。
5. **为 P1 增加稳定状态查询。** 当前主要在标签首次出现或变化时提问；下一轮可加入随机的标签不变前缀，区分真实状态维持和只检测变化点。
6. **把弃答作为独立训练/评测维度。** `drop_key` 和 evidence reveal 不应与普通方向准确率简单平均；分别报告 abstention precision/recall 和证据到达后的修正率。
7. **扩大模型面板。** 用至少一个不同架构或规模的 VLM 重跑 vision/vision-free。只有跨模型都出现的捷径风险，才更可能来自数据而不是单模型偏好。
8. **扩量前先冻结切分。** 按 scene 优先切分，trajectory 和 family 作为不可跨 split 的子簇；再生成和训练，防止同一家族变体泄漏。

## 不适合直接纳入主指标的 case

| case 类型 | 当前处理 | 原因与后续动作 |
|---|---|---|
| 单帧 P1 自运动题 | 已排除 | 没有可观察运动转移，只测几何约定 |
| compiler `invalid` 前缀 | 从未序列化 | `invalid` 是题目条件不成立，不能伪装为“无法判断” |
| 床存在性题 | 本轮排除 | 范围尚未完成；不影响其他题中把 bed 当普通实体 |
| 326 条 `shortcut_risk` raw | 保留但不单独作为能力证据 | 无视觉也恢复金标；需做标签对称化和跨模型复核 |
| `drop_key` | 保留为 abstention 子集 | 它测证据充分性，不应和普通方向题无区别地求平均 |
| 当前 P2/P3 两轮 streaming | 保留为 v1 evidence-update 基线 | 固定 `abstain→answerable` 结构可能在训练后形成轮次捷径 |
| P2 yaw 极低分 case | 保留并优先人工 review | 单模型低分不能证明题错；先核对视觉可读性、实体绑定和角度描述 |
| P3 当前 100 raw / 20 streaming | 只作开发诊断 | 覆盖过小且 vision-free 偏高，不能支撑总体 multiview correspondence 结论 |
| 语义正确但格式错误 | 保留，双指标报告 | 例如 `raw-6566...`；空间推理和协议遵从是两个问题 |

raw-0004 和 raw-0006 是 17 个批次中需要优先复核的两个批次。网页中选择对应批次后，可逐条对照多模态和无视觉回答。

## Review 后的决策边界

人工 review 可以否决视觉不可读、实体绑定错误、题面歧义或源文件损坏的样本；不能因为模型答错而修改 certificate 金标，也不能因为无视觉答对就直接删除样本。任何样本级变更都应回到 compiler、scene IR 或生成 policy，形成新的版本和可重复测试。

本轮可确认的是：数据已经提供了一套比普通单图多选题更严格的空间程序、证据干预和多轮状态更新评测；当前 SenseNova 在净转向、画面侧和部分基准参照系变换中表现出视觉收益，但在指回起点、带 yaw 变换、弃答和完整 streaming 状态更新上明显不足。是否能通过训练获得可泛化提升，仍需按上述消融和 held-out 设计实证验证。
